# Enterprise Private GPT — Локальная корпоративная RAG-система

Проект представляет собой защищенную локальную вопросно-ответную систему (RAG — Retrieval-Augmented Generation), разработанную в рамках домашнего задания по курсу LLM Engineering. Система предназначена для интеллектуального поиска информации по закрытой корпоративной/юридической базе документов и генерации точных ответов без отправки конфиденциальных данных во внешние облачные сервисы (все вычисления и данные полностью изолированы на локальной машине).

---

## 1. Стек технологий

* **Локальная LLM:** Qwen3 8B (запущена локально через LM Studio)
* **Модель эмбеддингов:** `text-embedding-nomic-embed-text-v1.5` (запущена локально через LM Studio)
* **Инструмент чанкования (Chunking):** LangChain `RecursiveCharacterTextSplitter`
* **Векторное хранилище (БД):** FAISS (Facebook AI Similarity Search) — индекс `IndexFlatL2`
* **Веб-интерфейс:** Gradio
* **Окружение и управление зависимостями:** Python 3.14 + `uv` для быстрого и детерминированного менеджмента пакетов.

---

## 2. Как работает Pipeline

Логика работы RAG-пайплайна состоит из двух основных этапов: подготовка базы знаний и выполнение пользовательских запросов.

### Схема обработки данных и генерации ответа:

```text
[Подготовка данных]
dataset/test.csv ──> Очистка текста ──> Чанкование (LangChain) ──> Генерация Embeddings (Nomic) ──> FAISS (.index)
                                                                                                      │
[Выполнение запроса]                                                                                  │ (Поиск Top-K)
Вопрос пользователя ──> Генерация Embedding ──> Поиск по расстоянию L2 (FAISS) ◄──────────────────────┘
                              │
                      [Проверка THRESHOLD]
                              ├───> Больше 0.28 ──> "В предоставленных документах информация не найдена." (Выход)
                              └───> Меньше 0.28 ──> Сборка контекста ──> Prompt ──> LLM Qwen3 ──> Ответ (Gradio)
```

1. **База документов (`dataset/test.csv`)**: Содержит юридические постановления и судебные решения.
2. **Очистка текста**: Нормализация пробелов, переносов строк, удаление управляющих символов.
3. **Чанкование (Chunking)**: Тексты делятся на перекрывающиеся фрагменты (`chunk_size=1000`, `chunk_overlap=150`) с помощью `RecursiveCharacterTextSplitter` для сохранения связности контекста на стыках.
4. **Векторизация (Embeddings)**: Для каждого чанка генерируется 768-мерный семантический вектор.
5. **Векторная БД (FAISS)**: Создается плоский индекс расстояний L2 (`IndexFlatL2`), обеспечивающий точный локальный поиск.
6. **Выполнение запроса (Inference)**:
   * Вопрос пользователя векторизуется через ту же модель эмбеддингов.
   * Выполняется поиск `Top-3` ближайших векторов в индексе FAISS.
   * Проверяется пороговое значение расстояния (`THRESHOLD = 0.28`): если расстояние больше порога, система считает, что информации по запросу в базе нет, предотвращая галлюцинации LLM.
   * Если релевантные чанки найдены, они объединяются в контекст и передаются в Qwen3 вместе с жестким системным промптом (`temperature = 0`).
   * Сгенерированный ответ выводится пользователю в Gradio с указанием исходных идентификаторов чанков (источников).

## 3. Подготовка данных и RAG-артефакты

Исходные данные для построения базы знаний берутся из файла `dataset/test.csv`, который находится в корневой директории проекта.

Поскольку сгенерированные поисковые артефакты имеют большой объем или динамическую природу, они **не хранятся в репозитории Git** (включены в `.gitignore`):
* `chunks.jsonl` — структурированные текстовые чанки с метаданными.
* `embeddings.npy` — сериализованный NumPy-массив сгенерированных векторов.
* `faiss.index` — скомпилированный бинарный файл поискового индекса FAISS.

Все эти файлы автоматически создаются при последовательном запуске ячеек в Jupyter Notebook:
`homework/Enterprise Private GPT/document_chunking.ipynb`

Перед первым запуском приложения обязательно откройте и выполните все ячейки данного ноутбука.

---

## 4. Инструкция по запуску

### Шаг 1: Подготовка окружения и зависимостей
Убедитесь, что у вас установлен менеджер пакетов `uv`. Синхронизируйте виртуальное окружение:
```bash
uv sync
```

### Шаг 2: Запуск LM Studio и загрузка моделей
1. Откройте **LM Studio**.
2. Скачайте и запустите большую языковую модель: `qwen3-8b` (или аналогичную Qwen 8B), модель эмбеддингов в комплекте: `text-embedding-nomic-embed-text-v1.5`.
3. Включите **Local Server** в LM Studio (порт по умолчанию `1234`). Убедитесь, что эндпоинт `http://localhost:1234/v1` доступен.

### Шаг 3: Генерация векторной базы знаний
Откройте и запустите по шагам ноутбук:
```bash
# Для запуска VS Code или Jupyter Notebook откройте файл:
homework/Enterprise Private GPT/document_chunking.ipynb
```
Убедитесь, что на диске появились файлы `chunks.jsonl`, `embeddings.npy` и `faiss.index`.

### Шаг 4: Запуск веб-приложения Gradio
Запустите интерфейс чат-бота:
```bash
uv run python gradio_app.py
```
После успешного запуска в консоли отобразится локальный адрес веб-интерфейса:
`Running on local URL: http://127.0.0.1:7860`

Откройте эту ссылку в браузере для работы с ассистентом.

## 5. Результаты тестирования системы

В соответствии с требованиями задания было проведено тестирование RAG-пайплайна по трем различным сценариям.

### Тест 1 — Запрос по базе знаний
* **Вопрос:** `Какие обстоятельства суд признал смягчающими наказание?`
* **Ожидаемый результат:** Система должна извлечь судебные решения, найти упоминания смягчающих обстоятельств и структурированно перечислить их.
* **Фактический результат:**
  > Суд признал смягчающими наказание обстоятельствами:
  > 1. Полное признание вины.
  > 2. Раскаяние в содеянном.  
  > 3. Активное способствование раскрытию преступления.
  > 4. Последовательные признательные показания Зонова С.В. (в ходе предварительного расследования).
  > 5. Наличие малолетнего ребенка.
  > 6. Психическое расстройство.
  >
  > Источники:
  > - Фрагмент базы знаний: 1532_9
  > - Фрагмент базы знаний: 2992_2
  > - Фрагмент базы знаний: 3175_5
* **Вывод:** Система отлично справляется с семантическим поиском юридических фактов и точно агрегирует их с помощью LLM.

### Тест 2 — Запрос вне базы знаний (Out of Domain)
* **Вопрос:** `Сколько дней в неделе?` (или любой отвлеченный вопрос, не относящийся к судебным делам базы)
* **Ожидаемый результат:** Отказ от ответа из-за превышения порога семантического расстояния (`THRESHOLD`).
* **Фактический результат:**
  > В предоставленных документах информация не найдена.
* **Вывод:** Пороговая фильтрация расстояния L2 в FAISS надёжно предотвращает обработку сторонних вопросов. Локальная LLM даже не вызывается, что экономит вычислительные ресурсы.

### Тест 3 — Тест на конфликт фактов
Тестировался вопрос по конкретному административному делу в отношении **Шевченко Андрея Витальевича** (статья 6.9 ч. 1 КоАП РФ).
* **Вопрос:** `Какое наказание было назначено Шевченко Андрею Витальевичу по статье 6.9 ч. 1 КоАП РФ?`
* **Обычный запрос к Qwen3 (без RAG):**
  > По статье 6.9 ч. 1 КоАП РФ (потребление наркотических средств) гражданам обычно назначается штраф в размере от 4 000 до 5 000 рублей или административный арест на срок до 15 суток. Конкретную информацию по Шевченко А. В. я предоставить не могу, так как не имею доступа к закрытым судебным базам данных.
* **Запрос через RAG-систему:**
  > Шевченко Андрею Витальевичу по статье 6.9 ч. 1 КоАП РФ было назначено наказание в виде **административного ареста сроком на 4 (четверо) суток**.
  >
  > Источники:
  > - Фрагмент базы знаний: 0_0
  > - Фрагмент базы знаний: 0_1
* **Вывод:** RAG успешно переопределяет общие знания языковой модели, заставляя её строго следовать фактам из локального документа. Вместо теоретических рассуждений или галлюцинаций модель выдает точечную, юридически достоверную информацию из конкретного судебного решения базы знаний.

## 6. Слабые места и ограничения

1. **Зависимость от качества эмбеддингов и чанкинга**: Если важная информация разрезана границей чанка посередине предложения, семантический поиск может сработать хуже, а модель — потерять логическую связь.
2. **Шум в результатах Top-K**: Метод поиска по евклидову расстоянию (L2) в FAISS может возвращать в тройке лидеров менее релевантные чанки, если они содержат схожие паттерны написания, но описывают другие дела.
3. **Статичность порога THRESHOLD**: Значение `THRESHOLD = 0.28` подобрано вручную экспериментальным путём. На другой базе данных или при смене модели эмбеддингов этот порог потребуется калибровать заново.
4. **Ограниченность контекстного окна**: При увеличении `Top-K` растет количество передаваемого в LLM текста. Для локальных моделей это может приводить к замедлению генерации и повышенным требованиям к VRAM (видеопамяти).
5. **Локальные аппаратные лимиты**: Скорость генерации и емкость базы напрямую зависят от производительности GPU. На маломощных компьютерах RAG-система может иметь высокую задержку (Latency) ответа.
